# J2534 July 2024 ISO fulfillment — staging only

This branch does not change the storefront, existing repair-product checkout, or any Cloudflare/PayPal settings. The intended price is USD 100.00 per copy; the ISO is J2534_July2024.iso, expected size 2732261376 bytes. The original Drive file URL, checkout URL, and account credentials are intentionally excluded from this repository.

## Configure

1. Verify the seller has distribution rights to the ISO. In Cloudflare create a private R2 bucket named j2534-private-downloads (no public URL), upload the original ISO as J2534_July2024.iso, and confirm the exact byte count and preferably the original SHA-256. Large uploads should use an S3-compatible multipart uploader such as rclone or aws s3 cp. Restrict the Drive source only after the verified private copy is available.
2. Create D1 database j2534-iso-sales using npx wrangler d1 create j2534-iso-sales. Copy wrangler.example.toml to wrangler.toml, replace the database ID, and initialize the database with npx wrangler d1 execute j2534-iso-sales --remote --file=schema.sql.
3. Run node --test test/*.test.mjs and node --check src/worker.mjs. Deploy the disabled Worker with npx wrangler deploy. Use the actual deployed URL, not a guessed URL.
4. In PayPal Business, locate the specific existing J2534 July 2024 $100 payment link. Verify its exact item name, unique item number if supported, one unit per purchase, correct currency, and set its inventory to three copies (less any copies already sold). Do not alter the separate $100 FRM3 product. Enable auto-return and Payment Data Transfer (PDT) in PayPal and set this specific payment link's confirmation/return URL to the actual Worker origin plus /return. Do not change other products' return URLs; if a per-link return is unavailable, stop rather than replace global settings.
5. Store PAYPAL_PDT_TOKEN, PAYPAL_MERCHANT_ID, PAYPAL_ITEM_NAME, DOWNLOAD_SECRET (32+ random characters), and PAYPAL_ITEM_NUMBER if PayPal provides an exact item number using npx wrangler secret put NAME. Never paste secrets into GitHub files. Use the verified PayPal item title and a unique item number if supported. Do not use price alone. The Worker deliberately refuses a payment when merchant, product, currency, amount, or completed status cannot be verified.
6. Validate PDT fields for this exact hosted payment link with a test checkout in a separate sandbox deployment using sandbox PayPal endpoint and credentials. Confirm the verified item identity and receipt transaction ID; if hosted links do not return the required verified PDT fields, implement verified PayPal webhooks with order/line-item lookup instead, and leave checkout closed. Do not test by charging a real buyer without their approval.
7. Only after storage, payment, duplicate/recovery and download/range tests pass, change ENABLED to true and redeploy. Confirm /health returns enabled=true and fileReady=true. Test recovery with receipt transaction ID and payer email. Then reopen only the J2534 product on the storefront with the supplied existing PayPal checkout URL. Do not expose the R2 object or Drive link.

## Behavior and limits

- PayPal returns the customer to /return?tx=... . The Worker exchanges that transaction ID with PayPal for verified payment details; it does not trust a browser's claimed success or price.
- The customer receives a 24-hour signed download link on the confirmation page; /recover lets the buyer regenerate it with their transaction ID and PayPal email. The R2 object is streamed with byte-range support.
- D1 records at most three unique verified transactions that claim a download. This does not prevent a fourth charge on the hosted PayPal link: configure inventory at PayPal before reopening. Handle any unexpected paid-but-unfulfilled purchase manually.
- No automatic email or webhook delivery, refunds/reversal synchronization, or production payment test is implemented in this staging version. If customers close PayPal before returning, recovery is required. A signed download URL can be shared until expiry; it is not a one-use token. Restrict/rate-limit recovery and return endpoints using Cloudflare before launch. Keep the checkout closed until the end-to-end flow is confirmed.
